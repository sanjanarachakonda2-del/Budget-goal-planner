# Budget Goal Planner

A beginner-friendly full-stack personal budgeting app built with HTML, CSS, Vanilla JavaScript, Node.js, Express, and Supabase PostgreSQL.

## 1. Project overview

Budget Goal Planner helps people plan how much they intend to spend in each category during a month, record actual expenses, and compare the two. It displays total budget, total spending, and the overall remaining amount, plus progress bars for each category.

### Problem statement

People can lose track of small day-to-day purchases and exceed their monthly spending limits. This application puts category limits and actual spending in one dashboard so users can spot overspending early.

### Objectives

- Create an account and securely sign in.
- Set one monthly limit per category.
- Record, search, filter, and delete expenses.
- View a month-by-month budget and spending comparison.
- Keep each user's data private from other regular users.
- Provide an administrator account that can view registered account metadata.

## 2. Roles and features

### Regular user
- Sign up and sign in.
- Create and update monthly category budgets.
- Delete a budget without deleting its expense history.
- Record expenses and view monthly expense history.
- Search descriptions/categories and filter by category.
- See spending progress and remaining-budget indicators.

### Administrator
- Has regular sign-in access.
- Can view a list of registered users' names, email addresses, roles, and account creation dates.
- Cannot view other users' expenses through the provided admin endpoint.

The admin account is created by the backend at startup using `ADMIN_EMAIL` and `ADMIN_PASSWORD` from `backend/.env`. Change the local placeholder to the supplied admin password before first launch. The password is hashed with bcrypt before being stored.

## 3. Technology stack

- HTML5: page structure.
- CSS3: responsive visual design.
- Vanilla JavaScript: browser interactions and `fetch()` API calls.
- Node.js and Express: REST API and server.
- Supabase PostgreSQL: persistent database.
- bcryptjs: password hashing.
- jsonwebtoken: signed, expiring API tokens.
- helmet: security-related HTTP headers.
- express-rate-limit: basic authentication endpoint rate limiting.
- dotenv: local environment variables.

No frontend framework or paid API is required. Google Fonts is an optional visual enhancement; the app remains usable if fonts cannot load.

## 6. Supabase setup

1. Sign in to Supabase and create a new project.
2. Choose a project name and a strong database password. Save the database password privately; it is not the same as the app admin password.
3. Wait for the database to finish provisioning.
4. In the Supabase dashboard, open **SQL Editor** and create a new query.
5. Copy all of `database/schema.sql`, paste it into the editor, and click **Run**.
6. Open **Table Editor** and confirm that `app_users`, `budgets`, and `expenses` exist.
7. Open **Project Settings / API Keys** (the exact menu label may vary). Copy the project URL and the server-side `service_role`/secret key. Never use a publishable/anon key for this backend's privileged database client, and never put a service-role/secret key in frontend code or GitHub.

This app uses custom application accounts in `app_users`, not Supabase Auth. The Express server is the only client of the database and performs authentication and ownership checks. RLS is enabled with no public policies, providing a barrier to direct browser access. The server-only service role bypasses RLS, so backend authorization is essential.

## 7. Configure environment variables

From the project root, open `backend/.env` in VS Code. It is included as a safe placeholder template; replace every placeholder with your own values.

```dotenv
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your_server_only_service_role_key
JWT_SECRET=your_long_random_secret
ADMIN_EMAIL=mrec@gmail.com
ADMIN_PASSWORD=the_admin_password_given_for_your_project
```

Generate a random JWT secret in PowerShell or any terminal:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Copy the printed value into `JWT_SECRET`. It should be at least 32 characters. Do not commit `.env`; `.gitignore` excludes it. `.env.example` contains variable names and safe example values and is intended to be committed.

The admin email is `mrec@gmail.com`. Set `ADMIN_PASSWORD` locally to the password supplied for your assignment before the first run. On startup, the server creates that admin account if it does not exist. Passwords are bcrypt-hashed in PostgreSQL. If you change `ADMIN_PASSWORD` after the admin account already exists, this simple bootstrap does not reset the stored password; update it through a secure admin/password-reset workflow before using this beyond a classroom demo.

## 8. Install dependencies and start the app

Open VS Code, choose **File > Open Folder**, and open the `budget-goal-planner` root folder. Open **Terminal > New Terminal**.

Run these commands from the `backend` directory:

```powershell
cd backend
npm install
npm run check
npm start
```

- `npm install` downloads the packages and creates `backend/package-lock.json`.
- `npm run check` checks JavaScript syntax.
- `npm start` starts Express and attempts to connect to Supabase during admin bootstrap.

Expected terminal output:

```text
Administrator account is ready: mrec@gmail.com
Budget Goal Planner is running at http://localhost:3000
```

The first line may say the administrator bootstrap was skipped if you have not configured the admin variables. A successful launch requires valid Supabase credentials and the SQL schema to have been executed.

Open **http://localhost:3000** in your browser. Do not open `index.html` directly from File Explorer: the app uses API routes served by Express.

To stop the server, focus the terminal and press `Ctrl+C`. For development with automatic restart, use `npm run dev`.

## 9. How to use the app

1. Create a regular account using **Create account**.
2. Choose a month using **Viewing month**.
3. Select **Set budget**, enter a category such as `Groceries` and a monthly limit, then save. Add more categories as needed.
4. Add an expense description, amount, category, and date, then choose **Record expense**.
5. Review the total spent and remaining amount. Category progress bars indicate how much of each limit has been used.
6. Search the expense list or filter by category.
7. Use **Edit** to change a category budget or **Delete** to remove a budget/expense after confirming.
8. Sign in with the configured administrator email and password to see the registered-users panel.

A category's name is used to match expenses to its budget. Use consistent category spelling (for example, `Groceries` each time). An expense may use a category without a budget; it still counts toward total spending.

## 10. Architecture

```text
Browser (HTML/CSS/Vanilla JS)
        | fetch() / JSON + Bearer token
        v
Express API (authentication, validation, ownership and role checks)
        | server-only Supabase client
        v
Supabase PostgreSQL
```

The browser stores the short-lived JWT in `localStorage` for this teaching demo and sends it in the `Authorization: Bearer ...` header. The API verifies the signature and expiry and reloads the user's role from PostgreSQL. Never trust a role or user ID sent by the browser. For production use, prefer secure HttpOnly cookies, add CSRF controls where appropriate, use a managed identity provider, and review the threat model.

## 11. REST API reference

All JSON error responses use `{ "error": "A friendly message" }`. Protected routes require `Authorization: Bearer <token>`.

| Method | Path | Access | Purpose / inputs |
|---|---|---|---|
| GET | `/api/health` | Public | Health check; returns service status. |
| POST | `/api/auth/signup` | Public, rate-limited | Body: `{ "name", "email", "password" }`; creates a regular account. |
| POST | `/api/auth/signin` | Public, rate-limited | Body: `{ "email", "password" }`; returns a token and safe user profile. |
| GET | `/api/auth/me` | Signed-in | Returns the current safe user profile. |
| GET | `/api/budgets?month=YYYY-MM` | Signed-in | Lists the signed-in user's budgets for that month. |
| POST | `/api/budgets` | Signed-in | Body: `{ "category", "amount", "month": "YYYY-MM" }`; creates a monthly budget. |
| PATCH | `/api/budgets/:id` | Owner | Body: `{ "amount" }`; updates a budget amount. |
| DELETE | `/api/budgets/:id` | Owner | Deletes the budget, not its expenses. |
| GET | `/api/expenses?month=YYYY-MM` | Signed-in | Lists the signed-in user's expenses for that month. |
| POST | `/api/expenses` | Signed-in | Body: `{ "description", "category", "amount", "spent_on": "YYYY-MM-DD" }`; records an expense. |
| DELETE | `/api/expenses/:id` | Owner | Deletes an expense. |
| GET | `/api/admin/users` | Admin only | Lists safe account metadata (maximum 500 users). |

Typical statuses: `200` success, `201` created, `400` invalid input, `401` missing/invalid token or credentials, `403` insufficient role, `404` record not found, `409` duplicate account/budget, `500` unexpected server/database failure.

## 12. Security notes and limitations

- Passwords are hashed with bcrypt; plaintext passwords are never stored.
- The server checks ownership in every budget/expense query and gets the user's role from the database.
- Authentication routes are rate-limited, JSON bodies are size-limited, and Helmet sets security headers.
- The Supabase service-role key and JWT secret are server-only.
- RLS is enabled without public policies. The privileged server key bypasses RLS, so route-level authorization is mandatory.
- JWTs expire after eight hours. In this MVP, signing out removes the token from the browser; there is no token revocation table.
- This is an educational starter app, not a financial product. It does not connect to bank accounts, import transactions, provide financial advice, or implement password reset/email verification.
- For deployment, use HTTPS, rotate all secrets if exposed, set production environment values, consider HttpOnly cookies and CSRF protection, and have the security model reviewed.

## 14. Troubleshooting

- **`SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY must be set`**: edit `backend/.env`; copy the project URL and server-side key from Supabase.
- **Startup failed / relation does not exist**: run all of `database/schema.sql` in the Supabase SQL Editor.
- **Invalid JWT secret**: generate a fresh secret using the command above and paste it into `JWT_SECRET`.
- **`fetch` or page cannot load**: start the backend and visit `http://localhost:3000`, not a `file://` URL.
- **Port 3000 is busy**: change `PORT=3001` in `.env`, restart the server, then visit `http://localhost:3001`.
- **Admin sign-in fails**: check `ADMIN_EMAIL` and `ADMIN_PASSWORD` in `.env`; if the account already existed before the password was set, this starter bootstrap does not overwrite its password.
- **`npm` is not recognized**: reinstall Node.js LTS and restart VS Code/terminal.
- **Git shows `.env` as staged/tracked**: stop before pushing; unstage it and remove it from tracking. If a secret was already committed or pushed, rotate it immediately; `.gitignore` alone does not remove it from history.
